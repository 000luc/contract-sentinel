## 1.3 登录复杂度分级

- [ ] A类：登录态稳定，可复用 Cookie
- [x] B类：登录态偶尔失效，需要人工重新登录
- [ ] C类：强风控/强验证码，不适合全自动登录

**判定依据**：
- 有图形验证码，增加自动登录难度
- 登录态仅维持1-2小时，非长期有效
- 但验证码为普通图片验证码，非滑块/短信/企业微信扫码
- 无设备绑定、无SSO

## 1.5 初步结论

**可行路线**：
1. **不自动登录**：因存在图形验证码且会定期退出，不尝试自动识别验证码或绕过登录
2. **复用已登录浏览器 Profile**：人工登录一次后，Playwright 复用该 Profile 的 Cookie/Session
3. **登录失效时停止并通知**：检测到登录失效弹窗时，停止运行并通知人工重新登录
4. **Playwright DOM 自动化为主**：待办列表是标准 HTML 表格，DOM 可读性高，适合 Playwright
5. **接口探索同时进行**：在 Playwright 操作页面时，观察 Network 面板，看是否有可用的后端接口

**风险点**：
- 浏览器 Profile 复用是否能在登录态过期前完成检查？（1-2小时窗口期）
- 如果待办量大，下载和审核时间可能超过登录有效期
- 需要验证页面是否检测自动化浏览器

**下一步**：进入阶段2，同时探索接口方式和 Playwright DOM 方式。
