# 阶段 2：OA 待办数据获取方式探索 —— Playwright DOM 自动化

## 2.1 探索目标

验证 Playwright 能否稳定操作泛微 e-cology OA 页面，读取待办列表并识别合同类流程。

## 2.2 测试环境

- 浏览器：Chromium（Playwright 内置）
- 登录方式：复用已登录浏览器 Profile（不自动登录，避开验证码）
- 测试页面：待办事宜列表页、流程详情页

## 2.3 待验证项目

### 登录态复用
- [ ] 能否复用 Chrome 的登录 Cookie/Session
- [ ] 复用后是否能直接访问待办页面（无需重新登录）
- [ ] 登录态过期时页面表现（弹窗？跳转登录页？）

### 待办列表读取
- [ ] 页面加载后待办列表是否正常渲染
- [ ] 表格行是否能用 Playwright locator 定位
- [ ] 能否读取每行的流程标题、流程编号、创建人等字段
- [ ] 合同类流程关键词筛选是否准确（"付款合同评审"等）

### 详情页操作
- [ ] 点击待办标题能否进入详情页
- [ ] 详情页是否正常加载
- [ ] "相关附件"区域是否可定位
- [ ] 附件链接是否可点击下载

### 特殊情况
- [ ] 页面是否有 iframe
- [ ] 弹窗/遮罩层是否影响操作
- [ ] 分页是否需要处理
- [ ] 页面是否检测自动化浏览器

## 2.5 判断标准

- [ ] 待办列表是正常 HTML 表格 → Playwright 适配度高
- [ ] 按钮、链接、附件都能定位 → 可进入 MVP
- [ ] 页面大量 iframe → 复杂度上升，但仍可做
- [ ] 页面是 Canvas / 远程桌面 / 图片流 → DOM 方案不可行
